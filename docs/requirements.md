# 系统需求说明

> 文档编号：REQ-01
> 编写日期：2026-10-20
> 阶段：第 2 阶段（需求核对）

## 1. 项目概述

校园二手交易平台：面向在校学生的二手物品（教材、电子产品、日用品等）在线交易系统。

用户可以在平台上发布闲置物品或求购信息，通过私信沟通，以「担保交易」模式完成买卖——买家付款后资金暂存平台托管，双方完成交付后买家确认收货，款项才结算给卖家；全程使用虚拟钱包与模拟支付，不涉及真实资金。平台由管理员负责商品与求购审核、用户管理、举报处理与提现审核，保障交易秩序。

解决的核心问题：校园内二手物品信息分散（多在 QQ 群/微信群，易刷屏、难检索、缺保障），本系统提供**集中发布、可检索、带信誉与资金托管**的交易闭环。

## 2. 用户角色

| 角色 | 说明 | 主要权限 |
|---|---|---|
| 普通用户 | 注册登录后**既能卖也能买**（不区分买家/卖家账号），是平台的交易主体 | 发布商品/求购、浏览检索、收藏、下单付款、确认收货、私信聊天、双向评价、举报、充值/提现、校园认证 |
| 管理员 | 平台运营与秩序维护者 | 商品/求购审核、用户管理（禁言/封禁）、举报处理、提现审核、分类管理、数据统计 |

## 3. 核心功能（MVP）

| 编号 | 功能 | 所属角色 | 优先级 | 说明 |
|---|---|---|---|---|
| F01 | 注册登录与校园认证 | 普通用户 | 必须 | 账号注册/登录；用户可在个人资料中填写学号+学校完成校园认证（简化版，不做真实学籍接口验证），管理员可查看认证信息 |
| F02 | 商品发布与审核 | 普通用户 / 管理员 | 必须 | 发布商品：标题、描述、价格、分类、多张图片；发布后进入「待审核」状态，管理员审核通过后才公开可见 |
| F03 | 商品浏览、搜索与筛选 | 普通用户 | 必须 | 商品列表页、按分类筛选、关键词搜索、商品详情页 |
| F04 | 收藏 | 普通用户 | 必须 | 收藏/取消收藏商品，个人中心查看收藏列表 |
| F05 | 求购信息 | 普通用户 | 必须 | 发布求购信息（想收什么、预算等），浏览求购列表，在求购下发起联系（进入私信）；求购信息同样需管理员审核 |
| F06 | 担保交易 | 普通用户 | 必须 | 下单 → 模拟支付（款项扣自买家钱包、转入平台托管）→ 双方完成交付 → 买家确认收货 → 款项结算至卖家钱包；订单状态完整流转（待付款→已付款待交付→已完成/已取消） |
| F07 | 虚拟钱包与充值提现 | 普通用户 / 管理员 | 必须 | 钱包余额、交易流水记录；充值：走模拟支付页（复用下单支付组件）；提现：提交后生成「处理中」记录，管理员审核通过后变为「已完成」并扣减余额 |
| F08 | 私信聊天 | 普通用户 | 必须 | 会话列表 + 一对一私信；实现方式**首选 WebSocket**（若实现困难，降级为定时轮询）；支持未读消息提醒 |
| F09 | 双向评价 | 普通用户 | 必须 | 订单完成后买卖双方互相评分+文字评价；卖家主页展示历史评价与平均分 |
| F10 | 举报机制 | 普通用户 / 管理员 | 必须 | 用户可对商品、留言或私信发起举报；管理员处理后可将违规商品下架、对违规用户禁言/封禁 |
| F11 | 管理员后台 | 管理员 | 必须 | 商品/求购审核、用户管理、举报处理、提现审核、分类管理、数据统计 |

## 4. 可选功能（加分项）

| 编号 | 功能 | 说明 |
|---|---|---|
| O01 | 平台数据统计图表 | 成交量、热门分类、活跃用户数等可视化图表 |
| O02 | 站内通知提醒 | 未读私信、订单状态变化、审核结果等消息提醒（简单站内信即可） |

## 5. 明确不做的事

- **真实支付**：不接入微信/支付宝真实扣款（需要企业支付资质，个人无法办理），统一用虚拟钱包 + 模拟支付实现担保交易逻辑。
- **真实学籍验证**：不调用学校学籍系统接口，校园认证仅做学号/学校登记，由管理员可查可管。
- **物流/快递跟踪**：交易以线下当面交付为主，不做物流模块。
- **复杂交易形态**：不做拍卖、秒杀、竞价、定金等。
- **移动端 App**：只做 Web 端（Vue 单页应用，可响应式适配手机浏览器）。
- **除私信外的实时推送**：不引入消息推送服务，系统通知走简单站内信。

## 6. 本科毕设体量评估

- **角色数**：2 类（普通用户、管理员）✅ 符合 2~4 类
- **核心模块数**：约 6 个 —— ① 用户与认证 ② 商品与求购（含审核） ③ 担保交易与虚拟钱包 ④ 私信沟通 ⑤ 评价与举报 ⑥ 管理员后台 ✅ 符合 3~6 个
- **预计工作量**：中等偏上。前端约 12~15 个页面（含管理后台），后端约 20+ 个接口；考虑到担保交易状态机与私信，建议预留 6~8 周开发时间。
- **风险点**：
  1. **WebSocket 私信**：实时通信复杂度较高，若实现遇到困难按约定降级为轮询（F08）。
  2. **担保交易状态机**：订单状态流转需严谨设计，防止重复付款/重复确认收货等并发问题。
  3. **钱包余额一致性**：付款、结算、提现都涉及余额变动，需要事务保证不出现金额对不上。
  4. **图片上传存储**：商品多图上传需确定本地存储方案（存本机磁盘目录即可，无需对象存储）。
